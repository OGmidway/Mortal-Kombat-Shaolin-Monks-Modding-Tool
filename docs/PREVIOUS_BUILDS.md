## Before choosing an older build

- Versions before **0.25.3** do not include the multi-action animation picker or the verified missing-metadata recovery workflow.
- Versions before **0.25.2** can create replacement-character batches the researched game draw path skips. Use a current build to compile replacements.
- Versions before **0.25.1** do not include successful-update old-EXE cleanup.
- Earlier releases may not understand newer edits, projects or native compatibility requirements. Keep original exports and project backups.

For the complete differences, read the [changelog](../CHANGELOG.md). A rollback changes Studio; it does not undo already-created ISOs or convert newer native data back to an older format.

## Use a previous build separately

1. Save your current project and close Studio.
2. Download an older **Windows ZIP** from the table and extract it into a new folder.
3. Use copies of your project/exports for comparison. Keep your original ISO intact.
4. Decline a newer-version install if you intentionally need to remain on that old build for a comparison. The updater does not perform downgrades.

Local updater cleanup only removes its own generated old-build backups after successful startup. It does not delete these GitHub releases or manually extracted archive folders.

## How this archive is maintained

The release-packaging process regenerates this index from the published GitHub release history, with the version being packaged marked current. Publishing includes committing the refreshed documentation and then making the new signed release latest. Older release assets, original tags, checksums and signatures remain intact.

The in-app updater continues to use GitHub's latest stable release, not this archive table. Documentation-only changes do not require reinstalling the application. Online guides may be newer than the copies in an older ZIP.

Earlier internal development packages are not public archive downloads. They can contain private application source and are not uploaded here.
